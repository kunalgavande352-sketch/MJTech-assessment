⚙️ Core Algorithms & Mathematics

1. Circadian Sleep Window Calculation (Modulo 1440)

Calculating bedtime backward from a wake time often wraps around midnight into the previous calendar day. We solve this using circular modulo arithmetic:

const [h, m] = wake.split(":").map(Number);
// Total minutes backward from midnight
const totalMinutes = h * 60 + m - (hours * 60) - fall;

// Modulo 1440 handles previous-day rollover cleanly
const normalized = ((totalMinutes % 1440) + 1440) % 1440;
const hh = String(Math.floor(normalized / 60)).padStart(2, "0");
const mm = String(normalized % 60).padStart(2, "0");

2. Multi-Factor Hydration Planner Formula

Combines body weight, activity, and climate adjustments, then accounts for the 20% water intake supplied by solid foods:

let ml = kg * 35; // 35 mL per kg base
if (activity === "moderate") ml += 350;
if (activity === "high") ml += 700;
if (climate === "hot") ml += 500;

const drinkMl = ml * 0.8; // 80% from direct beverages
const low = Math.round((drinkMl * 0.9) / 29.5735);  // Convert to fl oz (-10%)
const high = Math.round((drinkMl * 1.1) / 29.5735); // Convert to fl oz (+10%)

🔒 Privacy by Design & Security Safeguards

  • Zero Remote Transmission: Form submissions are handled via event.preventDefault(); inputs are never dispatched to a remote server.
  • RAM-Only Computation: Calculations occur purely in volatile memory. No cookies or localStorage persist user health answers.
  • XSS Prevention: Any user-provided note strings are sanitized with character entity encoding (notes.replace(/</g, "&lt;")) before DOM rendering.
  • No External Trackers: Zero third-party telemetry, ad beacons, or analytics scripts.

💬 Top Interview Questions & Answers

Q1: Why choose Vanilla JS instead of React or Vue?
Answer: "For this informational platform, React's virtual DOM and 150KB runtime bundle add unnecessary latency and build complexity. Vanilla JS gives us instantaneous first-contentful-paint (<200ms), 100/100 Lighthouse score, and demonstrates deep mastery of core browser APIs like URLSearchParams, DOM manipulation, and asynchronous Clipboard integration."
Q2: How does dynamic routing work on guide.html?
Answer: "Instead of 12 static HTML files, guide.html acts as a single dynamic reader. It parses window.location.search using new URLSearchParams() to retrieve the guide ID, queries our in-memory JavaScript dataset, dynamically renders the title, lede, body, and sources, and includes a safe fallback if an invalid ID is provided."
Q3: How did you ensure responsiveness without Bootstrap or Tailwind?
Answer: "I constructed a bespoke CSS system utilizing CSS Custom Properties for design tokens, CSS Grid with fractional units for card decks and footers, Flexbox for navigation, and mobile media queries at 768px and 980px. I also built a mobile navigation drawer with full ARIA accessibility."
Q4: What future enhancements would you build in v2?
Answer: "I would introduce PWA offline caching via a Service Worker, an imperial/metric unit toggle for hydration, client-side PDF checklist export, and a dark/light theme switch powered by CSS variables."
